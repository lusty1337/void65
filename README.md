# VOID65 — лендинг кастомной механической клавиатуры

Одностраничный промо-сайт в духе продуктовых страниц Apple. В центре —
одна непрерывная 3D-сцена: клавиатура стоит, опрокидывается к зрителю,
роняет колпачок, ловит его обратно уже внизу, разбирается на семь слоёв,
собирается, кувыркается за нижний край и проступает заново над ценой.

Вся геометрия строится кодом. Из внешних ассетов только колпачки —
`public/keycaps.glb` и вдвое более лёгкий `public/keycaps-low.glb` для
телефона, оба печёт офлайн-генератор (см. ниже), — и карта освещения
`public/hdri/studio.hdr`.

## Запуск

```bash
npm install
npm run dev
```

## Как устроена сцена

Канвас **один на всю страницу**, прибит к окну и лежит под содержимым.
Клавиатура не пропадает между секциями и не начинается заново в каждой —
она одна и та же. Отсюда сразу несколько вещей, которых иначе не добиться:
свет один на весь сайт, стыков канваса с фоном нет вовсе, а шейдеры
собираются один раз.

- `src/stage/acts.ts` — раскадровка в vh. Из этих же чисел берутся высоты
  секций в вёрстке, поэтому текст и камера не могут разъехаться.
- `src/stage/director.ts` — чистая функция `shotAt(p, fov, aspect)`: по доле
  прокрутки отдаёт весь кадр. Камера задана не координатами, а направлением
  съёмки, габаритом, который должен поместиться, и точкой взгляда — поэтому
  кадр не ломается на других пропорциях окна. Здесь же два набора кадров:
  для широкого экрана и для портрета.
- `src/stage/Stage.tsx` — единственный `<Canvas>`, `frameloop="demand"`.
  Прокрутку читает сам, на кадре: событие `scroll` и кадр браузера идут
  вразнобой, и камера, посаженная на значение из обработчика, повторяет
  этот разнобой рывками. Сглаживание — экспонента, поэтому обратный ход
  отыгрывается зеркально без единой отдельной строчки.
- `src/stage/rig.tsx` — свет: ключевой с картой теней, площадной софтбокс
  и два контровых, холодный и тёплый. Основную часть освещённости даёт
  окружение, лампы только доводят.
- `src/stage/ghost.tsx`, `reveal.tsx` — вход в два такта: сперва по модели
  волной проходит каркас, следом по нему нарастает материал. Отсюда же
  идёт и заставка: слои приходят в сцену по одному на кадр, и полоса
  загрузки показывает настоящие шаги подготовки, а не время.
- `src/stage/hover.tsx` — отклик клавиатуры: подъём клавиш под курсором,
  касание вместо свайпа на телефоне и нажатие настоящей клавиши
  на десктопе. Код клавиши приходит от железа, а не от раскладки системы,
  поэтому русская попадает в ту же клавишу (`keyboard/keyCodes.ts`).
- `src/stage/resolution.tsx` — плотность пикселей подстраивается под то,
  что железо тянет на деле: медленные кадры — ступень вниз, но не ниже
  пола из `quality.ts`.
- `src/stage/quality.ts` — уровни качества, см. ниже.
- `src/keyboard/**` — сама модель: стек слоёв с честными толщинами
  (`stack.ts`), вырезы в пластине, процедурные карты платы, атлас легенд.
- `src/page/**` — вёрстка поверх сцены, токены и выбор свитча на первом
  экране: он меняет цвет штоков и подсветки в сцене, строки характеристик
  в конце и пускает по плате волну света.

## Акты

| акт | что происходит |
|---|---|
| `hero` | клавиатура стоит; с первого же щелчка колеса заваливается к зрителю на 135° и поднимается. На вертикали с неё срывается случайный колпачок |
| `drop` | свободное падение: камера идёт рядом с колпачком, клавиатура растёт снизу |
| `build` | приземление, волна по раскладке, отъезд и разборка на семь слоёв по очереди |
| `order` | сборка НА СВИТЧИ (все слои сходятся одновременно), подброс, кувырок за нижний край, затем та же модель проступает заново над ценой |

## Колпачки

Геометрия печётся офлайн и лежит в `public/keycaps.glb`; тем же прогоном
собирается `keycaps-low.glb` — та же форма с вдвое меньшим числом сегментов
на фасках и в блюдце, её берёт лёгкий уровень:

```bash
npm run assets:keycaps
```

По мешу на каждую пару «ряд × ширина» — отдельные, чтобы фаски не
растягивались вместе с клавишей. Внутри: суперэллипс в сечении, блюдце
по r², запечённый в геометрию наклон ряда, и полноценная изнанка — юбка,
полость, потолок и бобышка с крестовым гнездом точно по штоку свитча.

**Легенда — часть материала колпачка**, а не отдельная плоскость сверху.
Она подмешивается во фрагментном шейдере по координатам его же геометрии
(`src/keyboard/legendPaint.ts`), поэтому лежит в блюдце, не может быть
перекрыта кромкой на пологом ракурсе и не стоит ни одного лишнего меша.

## Уровни качества

Считаются **один раз до первого кадра** (`src/stage/quality.ts`): менять
карту теней или набор материалов на живой сцене значит заставить three
пересобрать программы — те самые секунды блокировки, под которые выстроен
вход с заставкой. На ходу меняется только плотность пикселей: от неё
пересоздаются буферы, а шейдеры остаются. Решает не ширина окна, а тип
указателя и число ядер.

На лёгком уровне: облегчённая модель колпачков, карта теней вдвое меньше
и обновляется через кадр, окружение вчетверо меньше, фильтрация теней
проще, площадной источник один вместо двух, каркас на входе не строится,
стекло колпаков свитчей подделано смешиванием вместо настоящего
преломления, пружины внутри свитчей не строятся, полноэкранного SMAA нет.

Резкость при этом не режется. Многовыборочное сглаживание одинаковое
на обоих уровнях: оно считает освещение раз на пиксель и умножает только
покрытие краёв, поэтому на плиточной видеокарте телефона разрешается
в её же памяти и стоит дешевле лишней плотности. Сама плотность, спускаясь
под нагрузкой, не опускается ниже полутора — ниже начинается не мягкость,
а видимые пиксели на кромках корпуса.

Переключается вручную для проверки: `?q=low` и `?q=high`.

## Приёмка

```bash
npm test          # геометрия, раскладка, согласованность актов и вёрстки
npm run verify    # настоящий Chrome с GPU: снимки и три проверки числами
```

`verify` гоняет headless Chrome с `--use-angle=d3d11`, снимает вход и все
повороты сюжета в `verify-out/` и проверяет числами то, что по картинке
не видно: ошибки в консоли, реальный отклик клавиш на курсор и отсутствие
длинных блокировок главного потока после ухода заставки. Размер окна —
через `W` и `H`, адрес — через `VERIFY_URL`.

```bash
node scripts/bench.mjs --profile phone --tag base --shots
```

`bench` — стенд замера кадра: глушит цикл отрисовки, гонит страницу кадр
за кадром и отдаёт по каждому акту медиану, p90, отдельно время процессора,
вызовы отрисовки и треугольники. Профили `phone`, `land`, `mid`, `heavy`,
`desktop`, замедление процессора — через `--cpu`. С `--shots` снимает восемь
опорных точек сюжета: по ним сравнивается картинка до и после правки.

## Важно: пин postprocessing

`postprocessing` зафиксирован на **6.38.0**. В 6.39.x композер копирует
depth через `blitFramebuffer` в клон depth-текстуры (клон делит GL-ресурс
с оригиналом в three r152+) — на ANGLE/D3D11 это даёт `GL_INVALID_OPERATION`
каждый кадр при любом depth-эффекте. Не поднимать версию, пока баг
не исправлен.

## Стенд

`/lab.html` — отдельная страница для сборки модели: орбита, слои
по одному, ползунки корпуса, счётчик треугольников и кадров. На основном
сайте камера привязана к прокрутке, и деталь там не осмотреть.
